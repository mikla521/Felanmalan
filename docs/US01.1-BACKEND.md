# US01.1 – Backend för felanmälan (#35)

## Vad funktionen gör

`POST /api/felanmalan` tar emot en beskrivning och en kategori och sparar
ett nytt ärende i SQL Server med Entity Framework.

- `CreateTicketRequest` är en DTO med uppgifterna som användaren skickar in.
- `TicketCategory` är gruppens enum med Hardware, Software, Network och Other.
- `FelanmalanController` skapar en Ticket och sparar den med FelanmalanDbContext.

Beskrivningen får inte vara tom eller bara innehålla blanksteg. Kategorin måste
vara angiven och giltig. Felaktiga uppgifter ger svaret 400 (fel i anropet).
Kategorin kan skickas som namn eller som motsvarande tal 0–3.

När sparandet lyckas returneras 201 (skapat) med ärendet och dess Id.
Status sätts till New, TimeCreated sätts till aktuell UTC-tid och TimeStarted
lämnas tomt. Användaren kan inte bestämma dessa värden genom anropet.
I svaret visas kategori och status som enumtal, till exempel status 0 för New.

## Databasen

Filips anslutning i Program.cs används: SQL Server på localhost och databasen
Felanmalan, med Windows-inloggning. Detta är en lokal SQL Server, inte LocalDB.

TimeCreated har fått en privat setter så att Entity Framework kan spara och
läsa tiden. Migrationen AddTicketTimeCreated lägger till kolumnen utan att
ändra Filips första migration. För äldre ärenden som redan saknar sparad tid
blir värdet 0001-01-01; deras ursprungliga skapandetid går inte att återskapa.

Kör migrations med EF-verktyg version 10, från repots rot:

```powershell
dotnet ef database update --project Felanmalan.Server
```

Alternativt: välj Felanmalan.Server som standardprojekt i Visual Studios
Package Manager Console och kör `Update-Database`.
Båda migrations har redan körts på den här datorns lokala databas.

## Testning

18 HTTP-anrop har testats mot den riktiga servern på .NET 10 och den lokala
SQL Server-databasen. Testerna täckte giltiga kategorier, saknade uppgifter,
tom beskrivning, felaktig JSON och försök att ange backendens egna fält.

Sex giltiga anrop gav 201 och sparade ärenden. Felaktiga anrop gav 400.
Sparade värden kontrollerades direkt i databasen. Testärendena togs sedan bort.

Release-bygget passerar utan fel. Två namnvarningar kommer från klassnamnet
`initmigration` i gruppens ursprungliga migration. De hindrar inte bygget.
EF-kontrollen bekräftar att migrations stämmer med den aktuella datamodellen.

Exempel att testa manuellt finns i `Felanmalan.Server/Felanmalan.Server.http`.
Starta servern och kontrollera att adressen i filen stämmer med serverns adress.
Ett giltigt exempelanrop sparar ett riktigt ärende i den lokala databasen.
